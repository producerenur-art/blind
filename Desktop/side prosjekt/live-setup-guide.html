Live Broadcast Setup Guide Verified 20 Sep 2026

How to go live on SiriusFM with a Traktor Kontrol S2 — equipment, one-time setup and the routine to follow every session.

SiriusFM's live broadcast runs on WebRTC straight from your browser — there is no separate broadcasting app or server upload involved. Your DJ mixer's audio output is captured by the browser as a microphone-style input and sent directly to listeners in real time. This guide documents the exact gear and routing that has been tested end-to-end and confirmed working.

1. Equipment that works

Signal path

Traktor Pro 4 → macOS "Multi-Output Device" (Traktor Kontrol S2 MK2 + BlackHole 2ch, 44.1 kHz)
→ Chrome captures BlackHole 2ch (echoCancellation/noiseSuppression/autoGainControl: false, stereo)
→ WebRTC peer connection (Supabase Realtime signaling) → listeners' browsers

This is a different architecture from Ambient Mann's setup (Traktor → BUTT → Icecast/AzuraCast server). SiriusFM needs no separate broadcasting app or streaming server — everything happens in the browser.

2. One-time setup (do this once, not every session)

  1. Install BlackHole 2ch (free virtual audio driver) from the link above.
  2. Open Audio MIDI Setup (macOS) → click + → Create Multi-Output Device.
  3. In the new Multi-Output Device, check both Traktor Kontrol S2 MK2 and BlackHole 2ch.
  4. Set the sample rate to 44.1 kHz for the Multi-Output Device (not 48 kHz — a mismatch here can cause silent or distorted capture).

3. The routine — do this every time you go live

  1. System Settings → Sound → Output → select Multi-Output Device, and confirm the mute checkbox is not ticked. macOS remembers mute state per device separately, and BlackHole 2ch has repeatedly shown up muted again after switching devices — check this every time.
  2. Traktor → Preferences → Audio Setup → Audio Device = Multi-Output Device (not BlackHole alone, not the S2 MK2 alone — either one leaves a silent gap somewhere in the chain).
  3. Traktor → Preferences → Output Routing → set Mixing Mode = Internal (not External — External never sends a fully mixed signal to Output Master, even when the routing looks correct) → Output Master L/R = 1: Multi-Output Device L / 2: Multi-Output Device R.
  4. Play in Traktor and confirm you can actually hear the mix yourself (through the S2's headphone output) before continuing.
  5. On SiriusFM, click "Grant access" (reload the page first with ⌘R if a stale session is stuck) → confirm BlackHole 2ch (Virtual) is selected in the "Audio input" dropdown → click "Go live".
  6. Check that Sent (L)/(R) shows real dB values (e.g. −68 dB), not −∞ dB — that confirms audio is actually being captured and sent.

⚠ Known pitfalls

  • Never change your macOS audio device while a session is already live. Switching devices mid-broadcast silently breaks audio capture — no error message, just silence, even though the WebRTC connection still shows "LIVE". Always fully stop the broadcast (or reload with ⌘R) before changing any audio device setting, then start again.
  • Reinstalling the BlackHole driver breaks the existing Multi-Output Device. The new driver gets a new internal reference, so the old Multi-Output Device shows a ghost "disconnected device" row in Audio MIDI Setup. Fix: delete the Multi-Output Device entirely and rebuild it (re-check BlackHole 2ch + S2 MK2) after any BlackHole reinstall.
  • DSP must be off on the capture side. If the browser applies echo cancellation, noise suppression or auto gain control to the captured signal, it will audibly damage the music. SiriusFM's capture path already disables these — don't override it with different browser flags/extensions.
  • Accidentally enabling VoiceOver (⌘F5 is easy to hit by mistake) changes how clicks/navigation behave system-wide — check the top-left menu bar for a "VoiceOver" indicator if clicks suddenly stop landing correctly. Turn it off again with ⌘F5.

✕ Not required / don't do this

  • No separate broadcasting app (BUTT, OBS, Icecast client) is needed for SiriusFM — that architecture belongs to a different, unrelated project. SiriusFM streams straight from the browser via WebRTC.
  • Don't route BlackHole alone or the S2 MK2 alone into Traktor's Audio Setup — only the combined Multi-Output Device carries both monitoring and the browser capture correctly.
  • Homebrew is not required (and isn't supported on Intel Macs any more) — use the direct BlackHole .pkg download instead.
